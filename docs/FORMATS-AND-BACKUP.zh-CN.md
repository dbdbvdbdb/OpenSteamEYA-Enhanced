# 导入导出及备份格式

文件统一使用 UTF-8；可读带 BOM 的 UTF-8 文件，导出不加 BOM。密码空白、换行、引号、中文和分隔符按原值保存，不 trim 密码。

## TXT

兼容传统 `account----password` 每行一条，只拆分第一个 `----`，所以密码中其后的分隔符会保留；空密码允许。传统格式的反斜杠按原文，不自动推断转义。

本程序导出使用带版本标头的转义协议。每个字段内部 `\\` 表示反斜杠，`\h` 表示单个连字符，`\r`/`\n` 表示回车/换行。所有字段内连字符都转义，保证分隔符不与字段值混淆。

不包含备注和 SteamID 时：

```text
# OpenSteamEYA-TXT-v1 escaped
account001----password001
```

选择备注或 SteamID 时导出 v2，列固定为登录账号、密码、SteamID、昵称、备注；未选字段为空：

```text
# OpenSteamEYA-TXT-v2 escaped loginName,password,steamId,nickname,note
account001----password001----76561198000000001----我的账号----备注
```

CSV/JSON 更适合与其他软件交换；其他软件可能不识别 TXT 的版本标头与转义。

## CSV

必需表头 `loginName,password`，可选 `nickname,steamId,note`。支持引用字段、字段内逗号和换行、双引号用双写转义。重复表头或错误引用结构被拒绝，不把原密码内容拼进错误信息。预览的行号是该记录起始物理行；未闭合引用会拒绝整个文件。

```csv
loginName,password,nickname,steamId,note
"account001","password001","昵称","76561198000000001","备注"
```

## JSON

顶层为账号对象数组；字段大小写兼容 Web JSON，`loginName` 为非空字符串；`password` 默认为空字符串，显式 null 或非字符串拒绝。SteamID 可空，否则须为 17 位数字。

```json
[
  {"loginName":"account001","password":"password001","steamId":"76561198000000001","nickname":"昵称","note":"备注"}
]
```

普通导入不会接受文件注入的 ID、关联键、本地背景路径或分组引用。导入新账号生成 GUID，随后独立匹配原账号；已有登录名的导入只按策略更新密码，不偷偷改写身份与映射。

重复策略：跳过；覆盖已有密码（包括将密码置空）；仅当原密码为空时补充。检测大小写不敏感的登录账号，包含文件内重复。先预览再提交，一次原子写入。有效行可以导入，错误行计入失败统计；不存在部分数据库文件写入。

## ZIP 备份 v1

根 `manager.json` 为版本化的完整新增管理文档；图片在 `backgrounds/<资源名>`。不包含其他软件的凭证/Token，不加密。

0.2.3 继续使用文档版本 1，新增可选的账号 `groupIds` 数组保存多个分组 GUID；旧 `groupId` 仍保存第一个分组。读取旧备份或数据时自动将单分组纳入多分组列表，账号 ID、密码、备注及原关联键保持原值。替换恢复保留所有归属，合并恢复逐一按分组名映射到本地 GUID。默认分组为全部账号视图，不写入额外分组 GUID。

密码字段、TXT/CSV 转义规则和导入重复策略不变。普通账号导出/导入不携带有效分组引用；完整分组关系使用 ZIP 备份恢复。旧版程序只能理解第一个分组，降级后编辑数据可能丢失多分组归属，建议继续使用 0.2.3 或更新版本。

预览验证版本、重复登录名、GUID、分组引用、资源名、条目数量及总解压大小。未知版本、目录越界、重复资源名、异常大小或损坏结构拒绝。缺失图片清空该图片引用并回退莫奈背景。

合并：按登录名去重，按所选策略处理重复；导入的分组映射到现有同名分组，保持当前 UI 偏好。覆盖：以备份替换新增账号、分组和偏好，可修复损坏的 manager.json。两者都不读写原凭证文件。

先将图片写到新的随机资源名，再原子提交数据库；数据库提交失败时清理本次新建资源，旧数据仍可用。图片缓存不备份；恢复后重新生成。覆盖恢复未立即清除旧背景文件，避免故障时影响之前数据引用。
